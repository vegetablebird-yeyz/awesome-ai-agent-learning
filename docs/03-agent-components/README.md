> 作者：青松与桑叶
> 本系列教程定位：保姆级、通俗易懂、每一步都可运行、中文原创

---

如果把 Agent 比作一个人，那么：

- **大脑（LLM）** 负责思考和决策 —— 就像你的大脑一样
- **双手（Tools）** 负责执行操作 —— 就像你的手可以拿东西、打字、打电话
- **记忆（Memory）** 负责记住信息 —— 就像你的大脑能记住昨天发生了什么
- **策略（Planning）** 负责规划行动 —— 就像你做事情之前会先想好步骤

这四个组件缺一不可。没有大脑，Agent 无法思考；没有双手，Agent 只能"纸上谈兵"；没有记忆，Agent 每次都像失忆了一样；没有策略，Agent 遇到复杂任务就会手忙脚乱。

本章我们将逐一拆解这四大核心组件，帮你建立对 Agent 架构的完整认知。

## 3.1 大脑（LLM）：Agent 的思考引擎

在第2章中，我们已经详细学习了 LLM 的原理和调用方法。这里做一个简要回顾。

### LLM 是什么？

**LLM（Large Language Model，大语言模型）** 是 Agent 的"大脑"。它负责：

1. **理解用户的意图** —— 用户说"帮我查天气"，LLM 能理解这是要查天气
2. **制定决策** —— 决定该调用哪个工具、传什么参数
3. **生成回答** —— 把工具返回的结果组织成自然语言回复给用户
4. **逻辑推理** —— 在多步任务中进行推理和判断

### 为什么 LLM 是 Agent 的大脑？

你可以把 LLM 想象成一个"超级聪明但手无缚鸡之力"的专家：

```
┌─────────────────────────────────────────┐
│              LLM（大脑）                  │
│                                           │
│   能力：                                   │
│   - 理解自然语言 ✓                         │
│   - 逻辑推理 ✓                             │
│   - 知识问答 ✓                             │
│   - 代码生成 ✓                             │
│   - 决策判断 ✓                             │
│                                           │
│   不能做的事：                              │
│   - 上网搜索 ✗                             │
│   - 执行代码 ✗                             │
│   - 读写文件 ✗                             │
│   - 调用 API ✗                             │
│                                           │
└─────────────────────────────────────────┘
```

LLM 本身被"关"在服务器里，它只能接收文字、输出文字。它不能上网、不能执行代码、不能操作文件。但通过 **Function Calling** 机制，LLM 可以"指挥"外部代码去执行这些操作。

这就是为什么我们需要 **工具（Tools）**。

## 3.2 工具（Tools）：Agent 的双手

### 为什么 Agent 需要工具？

LLM 的知识有截止日期，它不能实时获取信息；LLM 不能执行代码，不能操作文件，不能访问数据库。如果 Agent 只有 LLM，那它就只是一个"百科全书"，而不是一个"助手"。

**工具让 Agent 从"只会说"变成"能做事"。**

举个例子：

| 没有 | 有工具 |
|-------------|-------------------|
| "北京今天天气如何？" → "抱歉，我不知道实时天气" | "北京今天天气如何？" → 调用天气 API → "北京今天晴，25度" |
| "帮我算一下 1234 * 5678" → 可能算错 | "帮我算一下 1234 * 5678" → 调用计算器 → "结果是 7006652" |
| "帮我查一下订单状态" → "我无法访问数据库" | "帮我查一下订单状态" → 查询数据库 → "您的订单已发货" |

### 工具类型

Agent 可以使用的工具种类非常多，以下是常见的几类：

```
┌──────────────────────────────────────────────────────────┐
│                    Agent 的工具箱                          │
│                                                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │ API 调用  │  │ 代码执行  │  │ 文件操作  │  │ 数据库查询 │ │
│  │          │  │          │  │          │  │          │ │
│  │ - 天气API │  │ - Python │  │ - 读写文件 │  │ - SQL查询 │ │
│  │ - 搜索API │  │ - JS执行  │  │ - 创建目录 │  │ - NoSQL  │ │
│  │ - 翻译API │  │ - Shell  │  │ - CSV处理 │  │ - 向量库  │ │
│  │ - 邮件API │  │          │  │          │  │          │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│                                                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ 网页浏览  │  │ 图像处理  │  │ 系统操作  │               │

│  └──────────┘  └──────────┘  └──────────┘               │
```

### Function Calling 机制简介

**Function Calling** 是 LLM 和工具之间的"桥梁"。它的原理其实很简单：

```
通俗解释：

1. 你告诉 LLM："你有这些工具可以用（天气查询、计算器...），每个工具的用法是这样的..."
2. 用户问了一个问题
3. LLM 思考后说："这个问题我需要调用天气查询工具，参数是 city='北京'"
4. 你的代码收到这个指令，实际执行天气查询
5. 你把查询结果告诉 LLM："北京今天晴，25度"
6. LLM 根据结果生成最终回答："北京今天天气晴朗，温度25度，适合出行！"

关键点：LLM 自己不执行任何代码，它只是"告诉"你的代码应该执行什么。
```

用代码来理解：

```python
"""
Function Calling 基本流程演示
"""
import os
import json
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("API_KEY", "your-api-key"),
    base_url=os.getenv("BASE_URL", "https://api.openai.com/v1"),
)

# 第1步：定义工具（告诉 LLM 有什么工具可用）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的当前天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "城市名称，如：北京、上海",
                    }
                },
                "required": ["city"],
            },
        },
    }
]

# 第2步：用户提问
user_question = "北京天气怎么样？"

# 第3步：LLM 决定是否调用工具
response = client.chat.completions.create(
    model=os.getenv("MODEL", "gpt-4o-mini"),
    messages=[
        {"role": "system", "content": "你是一个助手，可以查询天气。"},
        {"role": "user", "content": user_question},
    ],
    tools=tools,       # 传入工具定义
    tool_choice="auto", # 让 LLM 自己决定是否调用
)

# 第4步：检查 LLM 的决定
message = response.choices[0].message

if message.tool_calls:
    # LLM 想调用工具
    tool_call = message.tool_calls[0]
    print(f"LLM 要调用: {tool_call.function.name}")
    print(f"参数: {tool_call.function.arguments}")

    # 第5步：你的代码实际执行工具
    args = json.loads(tool_call.function.arguments)
    city = args["city"]
    result = f"{city}今天晴，25度"  # 模拟结果

    # 第6步：把结果返回给 LLM
    final_response = client.chat.completions.create(
        model=os.getenv("MODEL", "gpt-4o-mini"),
        messages=[
            {"role": "system", "content": "你是一个助手。"},
            {"role": "user", "content": user_question},
            message,  # LLM 之前要求调用工具的消息
            {
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result,
            },
        ],
    )
    print(f"最终回答: {final_response.choices[0].message.content}")
else:
    # LLM 直接回答，不需要工具
    print(f"回答: {message.content}")
```

> **注意**：第4章我们会手写一个完整的 Agent，那时会对 Function Calling 做更深入的实践。这里只需要理解"LLM 决策 → 代码执行 → 结果返回"这个流程即可。

## 3.3 记忆（Memory）：Agent 的记忆

人类的记忆分为短期记忆和长期记忆，Agent 也是一样。

### 短期记忆：当前对话上下文

短期记忆就是 Agent 在**当前对话**中记住的内容。它通过维护一个**消息列表**来实现：

```python
# 短期记忆 = 消息列表
messages = [
    {"role": "system", "content": "你是一个助手"},
    {"role": "user", "content": "我叫小明"},        # 用户说叫小明
    {"role": "assistant", "content": "你好小明！"},   # Agent 记住了
    {"role": "user", "content": "我叫什么？"},       # 用户问名字
    # Agent 能回答"你叫小明"，因为它在消息列表里"看到"了
]
```

**特点**：
- 只在当前对话中有效
- 对话结束后就消失了
- 受限于 LLM 的上下文窗口大小（通常几千到几万个 token）

### 长期记忆：跨对话知识存储

长期记忆让 Agent 能**跨对话**记住信息。比如你昨天告诉 Agent 你的名字，今天它还能记得。

实现长期记忆的方式有很多：

```
┌─────────────────────────────────────────────────┐
│              长期记忆的实现方式                     │
│                                                   │
│  简单 → 复杂：                                    │
│                                                   │
│  1. 文件存储（最简单）                              │
│     - 把重要信息保存到 JSON/TXT 文件               │
│     - 每次对话开始时读取                            │
│                                                   │
│  2. 数据库存储                                    │
│     - SQLite / PostgreSQL                        │
│     - 结构化存储，支持复杂查询                      │
│                                                   │
│  3. 向量数据库（最强大）                            │
│     - Chroma / Pinecone / Milvus                 │
│     - 支持语义搜索                                │
│     - 适合存储大量文本知识                          │
│                                                   │
└─────────────────────────────────────────────────┘
```

## 3.4 规划（Planning）：Agent 的策略

### 任务分解

面对复杂任务，Agent 需要"先想后做"。比如用户说"帮我策划一次日本旅行"，Agent 不能一上来就开始操作，它需要先规划：

```
用户任务：帮我策划一次日本旅行

Agent 的规划：
  步骤1：了解用户的预算和时间
  步骤2：搜索机票信息
  步骤3：搜索酒店信息
  步骤4：规划每日行程
  步骤5：估算总费用
  步骤6：整理成旅行计划文档
```

这就是 **任务分解（Task Decomposition）** —— 把一个大任务拆成多个小步骤，然后逐步执行。

### ReAct 模式简介

**ReAct（Reasoning + Acting）** 是目前最流行的 Agent 工作模式。它的核心思想是让 Agent **边思考边行动**：

```
ReAct 循环：

         ┌──────────────────────────────────────┐
         │                                      │
         ▼                                      │
    ┌─────────┐    ┌─────────┐    ┌─────────┐   │
    │  思考    │───→│  行动    │───→│  观察    │──┘
    │ Reason  │    │  Act    │    │ Observe │
    └─────────┘    └─────────┘    └─────────┘
         │
         │ 如果信息足够
         ▼
    ┌─────────┐
    │  回答    │
    │ Answer  │
    └─────────┘
```

用一个具体例子来理解：

```
用户：北京和上海哪个更适合周末出游？

第1轮 - 思考：我需要知道北京和上海的天气
第1轮 - 行动：调用 get_weather("北京")
第1轮 - 观察：北京晴天，35度

第2轮 - 思考：北京天气太热了，再看看上海
第2轮 - 行动：调用 get_weather("上海")
第2轮 - 观察：上海多云，28度

第3轮 - 思考：两个城市的天气都有了，可以给出建议了
第3轮 - 回答：上海更适合！上海28度多云，比较舒适；北京35度太热了。
```

## 3.5 Agent 架构总览

把四大组件组合在一起，就是一个完整的 Agent 架构：

```
┌─────────────────────────────────────────────────────────────┐
│                       AI Agent 架构                          │
│                                                              │
│  ┌─────────────────────────────────────────────────────┐    │
│  │                    用户输入                           │    │
│  └──────────────────────┬──────────────────────────────┘    │
│                          │                                   │
│                          ▼                                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              大脑（LLM）                              │    │
│  │                                                      │    │
│  │   理解意图 → 制定策略 → 选择工具 → 生成回答           │    │
│  │                                                      │    │
│  │   输入：用户消息 + 记忆上下文 + 工具定义              │    │
│  │   输出：自然语言回答 / 工具调用指令                    │    │
│  └──────┬───────────────────────────────┬───────────────┘    │
│          │                               │                     │
│          ▼                               ▼                     │
│  ┌───────────────┐              ┌───────────────┐            │
│  │  规划（Planning）│              │  工具（Tools）  │            │
│  │               │              │               │            │
│  │ - 任务分解     │              │ - API 调用     │            │
│  │ - 步骤排序     │              │ - 代码执行     │            │
│  │ - ReAct 循环   │              │ - 文件操作     │            │
│  │ - 反思纠错     │              │ - 数据库查询   │            │
│  └───────────────┘              └───────┬───────┘            │
│                                          │                     │
│                                          ▼                     │
│                                  ┌───────────────┐            │
│                                  │  记忆（Memory） │            │
│                                  │               │            │
│                                  │ - 短期记忆     │            │
│                                  │   (对话上下文)  │            │
│                                  │ - 长期记忆     │            │
│                                  │   (知识存储)    │            │
│                                  └───────────────┘            │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

用一句话总结：

> **Agent = LLM（思考） + Tools（执行） + Memory（记忆） + Planning（策略）**

这四个组件互相配合，让 Agent 能够像人一样理解需求、制定计划、使用工具、记住经验，最终完成复杂任务。

## 3.8 小结

本章我们从"人"的比喻出发，学习了 Agent 的四大核心组件：

| 组件 | 比喻 | 作用 | 关键技术 |
|------|------|------|---------|
| **大脑（LLM）** | 人的大脑 | 理解、推理、决策、生成 | LLM API、Prompt Engineering |
| **工具（Tools）** | 人的双手 | 执行实际操作 | Function Calling |

| **规划（Planning）** | 人的策略 | 分解任务、制定步骤 | ReAct、Plan-and-Solve |

理解了这四个组件，你就理解了 Agent 的完整架构。接下来的章节，我们将逐一深入每个组件，从零手写一个完整的 Agent。
